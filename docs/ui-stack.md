## 一、渲染栈：PySide6（Qt 6.11）

**选定**：PySide6 6.11 桌面应用，`QApplication` + `QMainWindow` + `QSplitter` 布局，令牌经 `theme.render_qss()` 注入 `theme.qss`。

**理由**（按硬约束逐条对）：

- 本产品的形态是**桌面常驻小工具**：托盘常驻、主窗口关闭即隐藏、只有托盘菜单能退出（`ui/app.py`）。`uis/UI_BASELINE.md` §八明确 Qt 的默认样式是「像半成品」的最大来源，本轮用 `theme.qss` 覆盖 20 类控件正面解决。
- 三条硬需求都落在本机，桌面进程比浏览器页更省事：**读麦克风原始流**（16 kHz 单声道 pcm_s16le，不落盘）、**读写本机 SQLite 台账**、**出站 HTTP 写回主数据系统**。
- `spec.md` 与 `task.json` 顶层 description 已经锁死「**无 HTTP 服务面、无 Web 控制台**」。选本地 Web 工作台就必须起一个 FastAPI 进程，与这条已锁定的前提冲突。

**否决**：

| 候选 | 否决理由 |
|---|---|
| 本地 Web 工作台（FastAPI + 静态前端） | 基线 §八说「带界面的核查工具默认选型应该是 Web」，但同条给了例外：必须与本地文件系统深度交互才选 Qt。本产品的录音不入库、不出本机，采集与识别全在本机进程内完成，且产品形态里明写没有服务面——为一个不需要远程访问的工具常驻一个 HTTP 服务，是给信息科白添一个端口与一个进程。若日后要跨机访问，这一项应当重选。 |
| Electron | 打包体积与启动时间都不适合「药学部共用 PC 装机后没人管」的场景；且要再带一套 Chromium 渲染，与已有的 Qt 渲染重复。 |
| Tauri | 同 Electron 的问题更重：本产品的 Web 侧没有前端资产可复用，为它硬造一层 Web 界面是把 PySide6 已有的控件重写一遍。 |
| 纯 CLI | 基线 §〇要求带界面的产出必须给界面；本产品的复核动作（对照现值/应为值/依据原文/状态）用命令行不成立。 |

**已知代价**：Qt 渲染与 Web 不同源，基线里 `rem`/`prefers-reduced-motion` 这类 Web 写法不能直接用；本轮用 `theme.duration_ms()` + `set_reduced_motion()` 做等价降级（见决策四）。

## 二、组件与样式方案：Qt 原生控件 + QSS 令牌模板 + `role` 动态属性

**选定**：

- 令牌层：`src/dmchange/ui/theme.py` 持有全部色值/间距/字号/圆角/动效时长；`src/dmchange/ui/theme.qss` 是模板，所有值写成占位符，启动时由 `render_qss()` 注入。**QSS 里不出现裸色值与裸字号**（基线 §一「令牌先行」）。
- 组件层：只用 Qt 原生控件（`QTableView` + `QAbstractTableModel` + `QSortFilterProxyModel`、`QLineEdit`、`QComboBox`、`QPushButton`、`QListWidget`、`QProgressBar`…）。表格按基线 §八第 3 条用 model/view，不用 `QTableWidget` 逐格塞。
- 语义样式：不用「到处 setStyleSheet」，统一走**动态属性 + role**（`role="title"` / `"evidence"` / `"field-error"` / `"status"` / `"card"` / `"section-title"`…），改完属性调 `theme.repolish()` 重刷。这样样式规则只有一份，集中在 `theme.qss`。

**理由**：本产品的界面元素只有 20 余种，全部是「输入 + 表格 + 详情」的形态，没有任何需要定制绘制控件的地方。原生的 `QTableView` 天然虚拟滚动，满足基线 §五「超过 200 行必须分页或虚拟滚动」。

**否决**：

| 候选 | 否决理由 |
|---|---|
| pyqt-fluent-widgets | **GPL-3.0**。基线 §八明写「院内闭源工具只能看结构与视觉，不能把代码搬进产品」。用它做视觉参照可以，搬进产品不行。 |
| qdarkstyle（MIT，可商用） | 许可证没问题，但它是一整套覆盖式主题，会把本产品自己的令牌体系顶掉；而本产品主色是石板蓝 `#2F5D8C`、底色是米白 `#F6F4EF`，与 Fluent 的蓝白体系不是一路。引它等于交出令牌主权。 |
| QtWebEngine + 内嵌 Web 前端 | 桌面里再塞一套 Web 渲染，令牌要写两遍、焦点与滚动行为两套、深浅色两套。基线 §八已把「令牌主权」列为硬约束。 |
| 全局 setStyleSheet 逐控件内联 | 就是本轮要清掉的「默认样式副产品」：改一处颜色要翻 8 个文件。改为 role 驱动后，`theme.qss` 是唯一样式真源。 |

## 三、图标与字体：内联 SVG + 中文系统字栈 + 等宽数字

**选定**：

- **图标**：内联 SVG 字符串放在 `src/dmchange/ui/icons.py`（mic / refresh / export），经 `QSvgRenderer` 渲染成 `QIcon`。SVG 里的描边色由调用方从令牌传入（`theme.ON_PRIMARY`），**源码里不写死色值**。已接两处：录音按钮的麦克风图标、详情页「刷新回执」的刷新图标。
- **字体**：中文走 `-apple-system / PingFang SC / HarmonyOS Sans SC / Source Han Sans SC / Microsoft YaHei` 系统栈（**不联网加载**，基线 §二：院内网通常出不去）；`QFont` 侧按候选顺序取系统里第一个真实存在的族（`theme._pick_family`），避免 CSS 式字体栈被当成单个族名而回落到默认字。
- **数字**：药品码/回执号/回执时间与含数字的现值/应为值，用 `QFont` 的 OpenType `tnum` 特性（等价 CSS `font-variant-numeric: tabular-nums`），保证纵向数字不跳字。药品码额外用等宽字族，23 位整码不截断。

**否决**：

| 候选 | 否决理由 |
|---|---|
| emoji 当图标 | 基线 §五明令禁止（「像 demo」的最强信号）；本轮机检 `EMOJI_ICON` 也是 0 命中。中文医院场景里 emoji 字形不可控，且跨机器渲染不一致。 |
| PNG 图标 | 基线 §五明令「不用 PNG 缩放」——缩放后边缘发虚。 |
| Qt 内置方块图标 / 主题自带图标 | 同条明令。 |
| Classic Elegant（Playfair Display + Inter，选型包候选） | Playfair Display 是衬线展示体，中文没有对应字族会落成宋体，与「密集核查表格」的调性冲突；且它需要联网加载，院内网出不去。 |
| Modern Professional（Poppins + Open Sans，选型包候选） | 思路对（现代无衬线），但 Poppins/Open Sans 同样要联网加载。折中：保留它的**调性**，把 Latin 标题字也换成系统栈，中文落到苹方/雅黑。 |
| 引入图标字体（Font Awesome / Material Icons） | 桌面端要额外打包字体文件并处理子集化；本产品只有 2 个图标，内联 SVG 更省。 |
| 数字列一律等宽（`font-variant-numeric` 之外再套等宽字族） | 回执时间等列用正文字族 + `tnum` 即可：数字等宽、中文照常；整列等宽会让 8 列表格视觉过重。只给纯编码列（药品码）用等宽字族。 |

## 四、动效：短、只改 opacity、可降级

**选定**：

- 令牌：`DURATION = {dur-1: 120, dur-2: 180, dur-3: 240, dur-4: 320}`（与基线 §六一致），缓动语义对应 `cubic-bezier(.2,.8,.2,1)` 入场 / `cubic-bezier(.4,0,1,1)` 出场。
- 实现：Qt 用 `QPropertyAnimation`（基线 §八第 7 条）。当前**只有一处动效**——toast 淡入 180ms（`dur-2`），只改 `opacity`，不动 `width/height/top/left`（基线 §六禁止）。
- 降级：`theme.set_reduced_motion(True)`（或环境变量 `DMCHANGE_REDUCED_MOTION=1`）后，`theme.duration_ms()` 一律返回 0，淡入动画直接不建，只保留状态切换本身。**这等价于 Web 的 `@media (prefers-reduced-motion: reduce)`**——Qt 没有 CSS 媒体查询、也读不到系统级「减少动态」偏好，所以用运行时开关 + 环境变量承载（`theme.qss` 头部注释里写明了这层映射）。

**否决**：

| 候选 | 否决理由 |
|---|---|
| Page Transition 200–300ms / 400–600ms（选型包两档） | 这两档是 **Web 路由切换**的时长。本产品没有路由，只有面板切换；400–600ms 落在「药事岗连续处理几十条条目」的场景里会累积成拖沓。 |
| 列表逐行淡入 / 表格滚动联动 | 基线 §六禁止「每个元素都加动效」「用动效掩盖加载慢」。条目表是核查表，用户的注意力在内容上。 |
| 入场位移动画（translateY 12–24px） | 动效位移会推迟首屏可读时间，且与「密集核查、要快」的场景冲突。当前 toast 只做透明度。 |
| 用 `QPropertyAnimation` 做整窗转场 | 一个常驻小工具没有转场场景。 |

## 五、数据可视化：不引入图表库

**选定**：**本轮不做任何图表**。可视化的职责交给条目表本身：状态列用语义色 + 状态文字（颜色不单独承载含义，基线 §四），配 `filter_by_status()` 状态筛选；药事会的汇总产物是 `export_csv()` / `export_markdown()` 导出的表，不是图。

**理由**：

- 基线 §〇「一屏一个主角」：这个工具的主张是**逐条可核对**（药品码 / 字段名 / 现值 / 应为值 / 依据原话 / 状态）。药事岗的问题是「这一条改得对不对」，图表回答不了这个问题。
- 基线 §七要求图表必带「空数据态、加载骨架、精度说明、导出按钮」——引入图表就是引入一整套新的验收面，而它服务的问题在院内并不存在（药品目录调整是**周频/事件驱动**的，不看趋势）。
- 状态色已经有 7 类（要素缺失/草稿/待复核/已提交/已确认/已驳回/已退回），再叠一张图就会撞上基线 §四「不超过 5 个语义色」和 §七「颜色不单独承载含义」。

**否决**：

| 候选 | 否决理由 |
|---|---|
| Qt Charts（QChart） | 要额外拉 QtCharts 依赖；7 类状态色无法映射到一张图的可读色阶；且图表的交互（缩放/框选）在这个核对场景里没有用途。 |
| ECharts + QWebEngineView | 等于在桌面里再塞一套 Web 渲染，令牌写两遍，与决策二冲突。 |
| matplotlib 导出的静态 PNG | 产物是「离线算出来的图」，药事会材料里不可交互、不可核对、也不带出处锚点；导出 CSV/Markdown 已经够用且每条都带原话与毫秒区间。 |

**保留的最小可视化**：条目表的状态列 + 状态筛选 + 悬停高亮。若将来真的要看「本周待复核条数随时间」，应新增一个**独立视图**而不是塞进主窗。

## 六、视觉验收方式：机检 + 真实渲染截图 + 逐张看图

**选定**（三层，缺一层都不算验收）：

1. **机检**：`python3 cf_ui_ref.py --audit drug-masterdata-change`。它查的正是本轮要清的东西：裸色值（`BARE_HEX`）、emoji 图标（`EMOJI_ICON`）、焦点样式（`NO_FOCUS_STYLE`）、降级块（`NO_REDUCED_MOTION`）、数字对齐（`NO_TABULAR_NUMS`）、令牌文件存在（`NO_DESIGN_TOKENS`）、Qt 专项（`QT_NO_QSS`）。
2. **真实截图**：`python scripts/capture_screenshots.py`，用 `QWidget.grab()` 抓**真实渲染结果**（套了真实 QSS、灌了真实条目数据），落 `docs/screenshots/`。禁止设计稿、禁止手绘、禁止占位图。
3. **逐张看图核对**：机检只查规则，查不出「药品码被截断了」「按钮被拉成整行横幅」「引用块红得像告警」这类问题。本轮就是靠看图发现了 3 个真问题并修掉（见下）。
4. **诚实标注**：README 的「概念 / 实测对照」小节写明哪一侧是目标、哪一侧是实测，差距记在 `docs/concepts/visual-target-gap.md`，不声称一致。

**视口集合**：`1440 / 1024 / 768` 三档 + **空态** + **错态**，共 5 张以上。

**否决**：

| 候选 | 否决理由 |
|---|---|
| 概念图与实测截图并排对照 | 本轮环境**不具备图像生成能力**。基线与 CLAUDE.md 都明令：没有图像能力时只保留结构化视觉目标卡，**不伪造图片、不放占位图**。 |
| Playwright 截图 | 产品不是 Web 栈。基线 §〇按渲染栈分别给验收方式：Web 用 Playwright，Qt 用 `QWidget.grab()`。 |
| 手工画「效果图」补齐差距 | 红线：禁止用设计稿/示意图冒充实测截图。差距要如实写进 gap 文档，不靠事后效果图抹平。 |
| 390px 手机视口 | 本产品是**桌面托盘常驻工具**，没有手机形态，390px 在院内场景不存在。桌面档位取 1440 / 1024 / 768 三档，其中 768 是院内老笔记本（1366×768）的可用宽度下限。 |
| 只做 3 张（够机检下限） | 机检只要 ≥3 张，但基线 §九要求四视口 + 空/错/加载态。本轮给到 5 张（含空态与错态），避免「刚好过线」。 |

**本轮靠「看图」发现并修掉的真问题**（机检查不出来的）：

1. 药品码被列宽截断成 `XC0014N01400140014E00…` → 药品码列固定 208px + 12px 等宽字（基线 §二 正文 12px 下限），整码显示不截断。
2. 「刷新回执」按钮被拉成整行蓝色横幅 → 动作按钮后加 `addStretch(1)`，按内容宽度。
3. 依据出处的引用块带 3px 砖红左边线 → 红色在本产品只表示「必须处理」，改为发丝边框（理由见决策三与 gap 文档）。
4. 1024 宽下「回执时间/经办人」被挤出视野 → 断点从 1000 上移到 1200，窄屏改上下排布让表拿整幅宽度。
5. 空态下详情页的依据行仍可点且是暖黄底 → 未选中条目时依据行禁用（米白底 + 占位色），状态标签隐藏。

## 附：与选型包候选的关系

`cf_ui_ref.py --brief` 给的候选是**素材不是结论**，本文件的六项决定与它们的取舍关系：

- 风格方向候选给了 **Data-Dense Dashboard**（BI/Analytics）与 **Flat Design**。本产品取 Data-Dense 的**密度取向**（行高 36px、13px 表格正文、8px 栅格）与 Flat Design 的**克制取向**（无渐变、无阴影、圆角 6px），但两者都偏「Web 仪表盘」，故不整体套用：本产品是核查工作台不是监控大屏，不做 KPI 卡片、不做图表。
- 配色候选给了 **Pharmacy/Drug Store**（绿 + 蓝）与 **Changelog/Release Notes**（灰 + 绿）。**否决绿主色**：绿在本产品已被「已确认」占用（医疗语境里绿是安全色，占主色会让状态色与品牌色打架）。实际取石板蓝 `#2F5D8C` 做主色 + 米白 `#F6F4EF` 做底 + 砖红 `#C0503A` 标错 + 墨绿 `#3F7A4F` 成功——按 `uis/huashu-design/references/design-styles.md` 的「采样 → 收敛 → 论证」三步法论证：**采样**取自医院场景的既有语义（药事会材料、目录单据的石板蓝与砖红印章色），**收敛**到 1 个主色 + 4 个语义色 + 1 组中性色，**论证**是「主色必须让位给状态色——药事岗看的是状态，不是品牌」。
- 动效候选给的是 Web 的 Page Transition 两档，**否决**（理由见决策四）。
- 字体候选的 Classic Elegant **否决**，Modern Professional 的调性保留但去掉联网字体（理由见决策三）。
